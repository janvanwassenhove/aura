UI/UX review & assessment

Grounded in the full console source (App.vue, tokens.css, all 19 components + stores). The faithful recreation is in AURA Console (Current); the proposal in AURA Console (Redesigned).

Verdict

The console is an unusually well-engineered UI — token discipline, honest failure states, real accessibility work — that has grown by accretion into three competing products: a robot remote control, a chat client, and a knowledge manager. The seams show as icon soup, scattered configuration, five status vocabularies, and a mode system that runs the whole backend but is invisible in the UI. Nothing needs to be thrown away; it needs one information architecture and one visual voice.

What is genuinely good (keep all of this)

Failure states that fix themselves

Robot offline shows the cause (mDNS vs refused vs timeout), an address field, and a network scan — right where the error is (U198–U200). Best-in-class.

Safety is designed, not bolted on

Labelled panic stop with spelled-out consequences (U192), approval gate with remember-choice, styled destructive confirms (U223), vault state that never lies (U180).

Token + a11y discipline

One tokens.css, no raw hex in components, AA contrast fixes (U215/U223), :focus-visible, reduced-motion support. Rare in a side project.

Micro-UX judgment

Shared tracking state so two switches can't disagree (U162), face-visible dot (U165), self-pacing camera loop, container-query input row. The details are loved.

Three redesign directions

All three keep every current function. They differ in what the product claims to be.

built as the mock

A — Mission Control

Mode-first. A Home / Work / Present switcher is the top-level control; it visibly sets the robot's boundaries (which tool groups are live). One status cluster, one activity rail, no modals — settings become a view.

Best when: the mode boundary story (your stated goal) is the product.

B — Companion

Chat-first. Richie's face, state and camera live in a persistent presence strip; brain and controls are slide-over drawers. Warmer, softer identity — feels like a creature, not a dashboard.

Best when: family members are the main users.

C — Workbench

Leans into VS Code: an icon activity bar with full views (Talk, Brain, Robot, Events, Config), command palette, dockable everything. The brain finally gets the room U228 fought for.

Best when: you (the operator/developer) are the only user.

What the redesigned mock changes, concretely

  • Mode switcher in the header — Home / Work / Present — with a capability strip showing exactly which tool groups the current mode permits (mail, calendar, dev, music, screen) and which are locked.
  • One status cluster: Brain · Robot · Vault as three consistent chips with one vocabulary; everything else (latency, realtime spend) moves into a hover/expanded detail.
  • Activity rail replaces title-bar icon soup + modals: Talk, Brain, Robot, Present, Events, Settings are peer views. Stop stays permanently visible.
  • Robot presence card: camera, state, follow/mic/awake and persona in one compact card; the 16-button gesture farm becomes a "Gestures" popover.
  • Settings consolidation: LLM, connections, appearance, capabilities and per-mode voice in one place, sectioned — no more env-var-only settings.
  • Visual voice: IBM Plex Sans/Mono, a calmer pine-green on warm paper (dark: deep evergreen), 2 radii, 5 type sizes, no emoji-as-icons.
